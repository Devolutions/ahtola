#   - turso/alter_column.sqltest (32 cases): ALTER TABLE ... ALTER COLUMN's schema-text
#     rewrite for FOREIGN KEY references consistently drops the space before "(" that Turso's
#     corpus expects (e.g. "REFERENCES parent(id)" vs "REFERENCES parent (id)"), and
#     "ALTER COLUMN ... TO ... AS (...)" (converting a column to/from a generated column) is not
#     implemented at all ("ALTER COLUMN to a generated column is not supported").
#   - turso/attach/writes.sqltest (21 cases) + turso/attach/cross_db_views_rejection.sqltest
#     (9 cases): Ahtola's managed ATTACH deliberately rejects cross-database JOINs, INSERT
#     SELECTs, subqueries, multi-database transactions, and schema-qualified CREATE VIEW/DROP
#     VIEW ("Cross-database statements are not supported by managed ATTACH", "Managed ATTACH
#     transactions cannot modify more than one database..."), where Turso supports all of
#     these; turso_cdc (change-data-capture) is also not implemented.
#   - turso/analyze.sqltest (5 cases): ANALYZE does not create/populate sqlite_stat1 for
#     :memory: databases ("no such table: sqlite_stat1"), and analyzing a WITHOUT ROWID table
#     does not reject as the pinned corpus expects.
#   - turso/attach/sequence.sqltest (4 cases) + turso/mvcc_sequence*.sqltest (8 cases):
#     schema-qualified/attached-database SEQUENCE state does not appear to be scoped per
#     schema the way the pinned corpus expects (values interleave across what should be two
#     independent sequences).
# These are genuine, precise, per-case differences (not harness limitations) recorded below for
# the coordinator's ownership; COVER does not implement engine fixes.
